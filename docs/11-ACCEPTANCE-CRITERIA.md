# 11 — Acceptance Criteria

## A. Product and policy

- [ ] Product is a web Voice Studio, not a mock demo.
- [ ] No neural, statistical/ML, LLM, cloud, cloned, or generative speech synthesis.
- [ ] Every enabled engine has compliance and license evidence.
- [ ] No external speech API is required for runtime.
- [ ] UI accurately distinguishes native controls, DSP controls, and unsupported controls.

## B. Identity and projects

- [ ] User can register, sign in, sign out.
- [ ] User can create, rename, duplicate, archive, and delete projects.
- [ ] Project ownership is enforced on every endpoint.
- [ ] Project and segment settings persist after reload.
- [ ] Autosave reports saving/saved/error states.

## C. Text and voice

- [ ] User can enter Unicode text.
- [ ] User can split, merge, reorder, and edit segments.
- [ ] User can choose a verified locale/voice combination.
- [ ] Unsupported locale/voice combinations are rejected clearly.
- [ ] Pronunciation overrides work deterministically.
- [ ] Normalized text can be inspected.

## D. Synthesis and DSP

- [ ] Real audio is generated by an approved local engine.
- [ ] Preview works for one segment.
- [ ] Speed, pitch, and volume behave as documented.
- [ ] Pause insertion is sample-accurate within expected tolerance.
- [ ] DSP does not silently clip output.
- [ ] Re-render after a segment edit updates only affected assets where possible.
- [ ] Cache invalidates when any synthesis-affecting input changes.

## E. Timeline and export

- [ ] Waveform is based on actual generated audio.
- [ ] Playback, pause, seek, and segment navigation work.
- [ ] Project render assembles segments in correct order.
- [ ] WAV export decodes successfully.
- [ ] MP3 export decodes successfully when enabled.
- [ ] Export metadata matches selected output profile.
- [ ] Download is authorized and functional.

## F. Jobs and resilience

- [ ] User sees queued/running/succeeded/failed/cancelled states.
- [ ] Progress reflects actual completed work units.
- [ ] Failed jobs expose safe actionable errors.
- [ ] Retry does not create duplicate inconsistent assets.
- [ ] Worker restart does not corrupt project state.
- [ ] Previous valid export remains available if a new render fails.

## G. Deployment and quality

- [ ] Clean Docker Compose deployment succeeds from docs.
- [ ] Migrations work on empty database.
- [ ] Health/readiness checks work.
- [ ] No critical browser console errors.
- [ ] No critical API/worker errors.
- [ ] P0 automated tests pass.
- [ ] Security checks pass.
- [ ] Backup and restore procedure is verified.
- [ ] Released voice/locale combinations pass manual QA.

## Release gate

Do not declare production-ready while any P0 item is unchecked, any enabled engine is unverified, or a user cannot complete create → synthesize → preview → render → download.
