# 06 — Production readiness

Date: 2026-10-31. Scope: the upgraded application with eSpeak NG as the only usable speech engine.

## Verdict

**Not declared production-ready.** The application runs, builds and deploys from a clean checkout on a single node and passes its automated and black-box checks. Four acceptance conditions are **not met**, and are listed first so they are not missed:

| Not met                                         | Why                                                                                                                                                                                                                                                                   | What would close it                                                                                                              |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Docker build and Docker Compose deployment      | Docker is not installed on the QA machine. `infra/docker/Dockerfile` and `docker-compose.yml` have never been built or run (only statically reviewed)                                                                                                                 | Run `docker compose build && docker compose up` on a machine with Docker and repeat `qa-functional` and `qa-security` against it |
| Human listening evaluation of Vietnamese speech | An automated agent cannot listen; no listener has rated the pack                                                                                                                                                                                                      | A native speaker completes `qa-output/sample-pack/listening-sheet.csv` (see 05-QUALITY-REPORT)                                   |
| Redis connectivity                              | **Not applicable by design**: the job queue is PostgreSQL (`SKIP LOCKED` leases, LISTEN/NOTIFY), see ADR 0003. No Redis service exists in compose or code. `docs/10-DEPLOYMENT.md` still lists Redis from the original plan and should be read together with that ADR | Done: a status note at the top of `docs/10-DEPLOYMENT.md`                                                                        |
| A replacement Vietnamese engine                 | `vnunit` has no licensed data and is not admitted                                                                                                                                                                                                                     | Licensed recordings, build a database, native-speaker evaluation, admission record                                               |

### Clean-environment run (non-Docker)

1. Copied the source tree without `node_modules`, `dist`, data, storage, tmp or `.env`.
2. `pnpm install --frozen-lockfile` (online, 76 s) succeeded.
3. Wrote a fresh `.env` from `.env.example` with a new secret, a **new empty PostgreSQL database** and port 4100.
4. `pnpm build` succeeded (contracts, db, core, api, worker, web).
5. `node scripts/start-all.mjs` applied all 3 migrations to the empty database, started API and worker; `/health/ready` reported database, storage, engine (eSpeak NG 1.52.0), FFmpeg and worker all ok.
6. `qa-functional`: **24/24**; `qa-security`: **22/22** against that instance.

A first attempt at step 4 failed only because the copy command excluded the directory name `storage` everywhere, including `packages/core/src/storage`; this was a mistake in the copy, not in the project (`.dockerignore` excludes only the top-level `storage`).

## Performance summary

Real-time factor 0.021 for a cold 8-paragraph render, 0.014 aggregate for 6 concurrent projects, preview latency p50 155 ms, cache re-render 0 ms, about 700 MB total resident memory including PostgreSQL. Details and limits in 05-QUALITY-REPORT §6.

## Known risks

1. Vietnamese speech quality is unrated by listeners; the Central voice's tone contours are almost flat by measurement.
2. Docker path untested.
3. Load beyond the tested size (8 paragraphs × 6 projects) is unmeasured.
4. The `vnunit` engine and its voice-library paths are exercised only with synthetic fixtures.
5. CI is not set up (needs the Docker image; see UP-011).

## Addendum (2026-10-31): optional AI voice engine

The verdict above still stands for the rule-based engines. With ADR 0008 the application can additionally use a **self-hosted AI voice** (VieNeu-TTS) in a separate service. What that changes for readiness:

- "The selected engine is non-AI" now holds for the default engines only; the AI engine is opt-in, labelled "AI" everywhere, isolated (internal network, token, preset voices) and checked by the compliance audit (URL must be internal, ADR present, application image excludes the service).
- Verified with the real model: 24/24 functional checks with an AI voice (preview, render, WAV and MP3 export, reopen, re-render), 13/13 service checks, Playwright 5/5, priority behaviour under load (see `09-AI-ENGINE-CAPACITY.md`). Vitest 255/255, lint and format clean.
- **Still not verified:** Docker (also the new `vieneu` image and compose profile), any VPS, capacity beyond 2 model instances, long-running stability, whether the AI voices sound natural and pronounce correctly (nobody has listened), and the model author's statements about licence and speaker consent.
- Plans are assigned by an administrator; there is no billing.
